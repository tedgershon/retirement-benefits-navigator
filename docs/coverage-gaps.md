# Eligibility ruleset coverage gaps

All eight preliminary program definitions in `data/curated/programs/` have the owner's approval for discovery screening. No definition is a comprehensive agency determination.

This register lists **general rules and algorithms still absent or compressed into verified input fields**. It does not list facts to collect about a particular person. Public sources establish many of these rules; completing them means decomposing them into reusable expression branches or calculation logic. A case-specific input that applies an already modeled rule is not itself a ruleset gap.

The program JSON files contain no review questions, calculation notes, review status, or revision field. They can contain evidenced `follow_up` actions separate from discovery screening. The screens retain unknown pathways; five definitions mark peripheral child, student, disability, and custodian routes explicitly unknown while common older-adult routes remain testable. The research backlog is described here rather than in each program document.

## Input-backed formulas already represented

The schema permits a threshold row to use `input_field` instead of a fixed `value`. The matcher returns `unknown` when that input is missing or invalid. This represents the known comparison rule without pretending that a single numeric limit applies universally. The remaining **ruleset work** is to implement the calculation named below, not to gather anyone's records:

| Input-backed threshold | General calculation to encode |
| --- | --- |
| `ssi_applicable_monthly_federal_rate_cents` | Federal rate selected by SSI category and living-arrangement rules, compared with monthly countable income using strict `<`. |
| `va_applicable_mapr_cents` | VA Veterans Pension base MAPR selected by tier and dependent category, plus the published additional-dependent amount where applicable. |
| `va_applicable_survivor_mapr_cents` | VA Survivors Pension base MAPR plus additional-child amount, or the distinct surviving-child custodian formula under 38 CFR 3.24(c). |

The new official POMS and CFR references in the definitions were read through the web tool. Their evidence entries give a URL and section locator and deliberately have **no source ID or raw snapshot**. Capturing those sources and verifying the resulting hashes is a source-provenance task before a fully reproducible evidence set can be claimed.

The `definitions` command validates all eight program documents and their source references. All eight are accepted by normal `match`; PostgreSQL integration is deferred. Structural checks and synthetic tests do not resolve the ruleset gaps above.
